# MAA 后台推图助手

本地程序通过 ADB 与 MAA v6.20.1 核心操作指定模拟器；不操作 Windows 桌面、鼠标或键盘，不自动打开浏览器。服务仅监听 `127.0.0.1:18741`。安装目录名虽为 v6.9.5，实际 DLL 版本为 v6.20.1。

## 使用

1. 保持模拟器中的游戏已登录，MAA 日常任务处于空闲状态。
2. 双击桌面 **MAA 自动推图助手** 图标，自动启动后台并打开独立控制窗口；无需另行启动 Python。重复点击会回到已有窗口。也可在窗口中打开 <http://127.0.0.1:18741> 网页控制台。
3. “扫描未通关关卡”读取全目录普通和可见突袭进度，逐关保存并继续检查缺项；手动打过关卡后，可通过“辅助操作 → 重新识别本章进度”刷新旧记录。表格状态筛选“待通关”显示确认的未通关、未满星关卡。
4. “开始本章推图”刷新干员后自动扫描、筛选、演习和正式作战；“全目录推图”先处理已知缺关，再处理其他分区。全部分区共用每轮预算。只扫描任务不会开始战斗；扫描未完整时会保存并明确显示缺项。
5. 点击“停止当前任务”或双击 `停止当前任务.vbs` 可停止操作并保留进度。游戏可能留在战斗画面，助手不会擅自弃战。

当前每轮 **正式作战、演习尝试和单关候选均不限次数，最多200 理智预算**，可在 `settings.json` 调整。不吃药、不用源石；作业只缺 1 名干员且技能要求不超过 7 级时可借 1 名助战，自有干员方案优先。按授权，仅为作业实际需要的三星至五星干员补基础技能至最高7级，缺料可按需合成；不自动升级、精英化或专精。使用并重新编排第 **4** 编队。预算在同一次全目录任务中共享，不会切换章节或续跑后归零；演习累计次数不是游戏内剩余演习券数量。

## 当前实现

- 每次推图先通过 MAA `OperBox` 刷新干员。长任务中，正式候选演习前检查 30 分钟有效期，过期重新扫描。有效字段、完成回调和至少 95% 历史 ID 覆盖校验后，备份并写回 `../data/OperBoxData.json` 以及 `runtime/operators.json`。
- 0.7.0 在刷新前清除职业筛选并重置列表；对候选干员补读技能等级、专精和当前装备模组，经过身份、页面和两帧核验后写回 MAA。未识别字段仍为未知，详情缓存最长 30 分钟。单关尝试次数与阶段持久化，失败记录只关联实际阵容。详见 [0.7.0 逻辑与实机验证](LOGIC_RELEASE_0.7.0.md)。
- 目前快照为 316 名。历史少见到的“德·托莱多”保留在差异记录，不虚构为当前可用干员。MAA GUI 可能缓存列表；磁盘已更新，未操纵桌面强制刷新 GUI。
- 目录包括主线及常驻支线 **59 个章节、170 个地图分组、1,145 个战斗关卡、1,877 条难度记录**，另记录 159 个剧情节点。这是游戏数据目录规模，不是已验证自动通关数量，也不是用户未通关数量。
- 普通、突袭、其他难度用不同进度键保存。突袭识别第四枚白色通关标记，不能把普通模式的三枚蓝标当作突袭完成。
- 网上作业使用公共只读接口，按关卡精确核验并区分 difficulty=1 普通、2 突袭、3 两者。替换组使用不重复干员分配，已知练度不足阻断。未提供的专精、模组、信赖不会当成已满足。
- 每个候选先做真实演习。必须取得正确模式开始回调、目标关卡结算成功证据，再允许正式作战。正式结算后重新读取关卡通关标记。
- 使用 MAA 原有识别模板，保存每一帧结算图与 OCR/匹配分数。结算页的关卡编号不再误判成地图节点，加载中等待而不盲点。
- 通关后增量扫描新解锁和待确认关卡；同一轮已有普通及突袭完整通关证据的节点不会反复点开，未知或尚未确认的突袭继续检查。首次账号扫描仍全量执行。
- 已确认的演习失败会持久化记录；只在明确退出失败结算并重新确认目标关卡、难度后更换作业。达到本关上限或候选用完后跳过本关，继续其他关卡。相同作业内容和干员条件下的失败组合在重启后仍排除；作业内容或干员实际条件变化后可重新评估。正式失败、设备异常、模式或结算不明、恢复失败会停止整轮。详见 [0.6.0 逻辑优化与验证](LOGIC_OPTIMIZATION.md)。
- 全任务互斥锁覆盖扫描、筛选、推图；设备锁保护游戏操作。服务重启可识别存活 worker；PID 创建时间防止 PID 重用误判。新请求之后的 STOP 不会被启动逻辑删除。
- 控制页可搜索完整目录、筛选待通关/突袭/未扫描/阻塞项，显示真实账号扫描和候选作业。完整进度报告为 `runtime/coverage.json`、`coverage.csv`。

## 文件和依据

- `data/catalogue.json`：本次游戏数据编译结果、源文件哈希、分组、难度、剧情节点与前置条件；`build_catalogue.py` 为编译工具。
- `runtime/progress.json`：账号扫描记录和证据路径，不是游戏存档。
- `runtime/jobs/`：原始和限定编队后的作业文件。
- `runtime/attempt-history.json`：按关卡、难度、作业内容和干员条件保存的失败/通过记录。
- `runtime/screens/settlements/`：按关卡、模式、演习/正式分类的逐帧结算证据。
- `runtime/campaign-results.json`、`scan-report.json`：全目录执行/扫描结果。
- `runtime/run-results.json`、`activity.log`、`core-events.ndjson`：执行日志；`runtime/backups/` 保存旧快照与修复前记录。
- `tests/`：可独立运行的回归测试。运行时测试在本项目 `_tmp/` 内创建受控副本，使用假的游戏模块，不连接真实模拟器；完成后仅清理对应测试目录。

实现参考 [MAA v6.20.1 开源代码](https://github.com/MaaAssistantArknights/MaaAssistantArknights/tree/v6.20.1)、[MAA 作业协议](https://docs.maa.plus/zh-cn/protocol/copilot-schema.html)、[公开游戏数据目录](https://github.com/Kengxxiao/ArknightsGameData/tree/master/zh_CN/gamedata/excel)。不修改或重新分发原 MAA DLL、资源任务；上游许可证继续适用。

## 断点续跑

连接中断或 ADB 权限/超时错误会停止整轮任务。设备恢复后可点击“继续上轮全目录任务”，或运行 `python worker.py resume-all`。这会沿用上轮剩余预算，跳过已完成扫描的分区并重试失败分区；不会把次数和理智重新加满。需要新预算时使用“按全目录推图”。原检查点另存于 `runtime/backups/campaign-*.json`。
